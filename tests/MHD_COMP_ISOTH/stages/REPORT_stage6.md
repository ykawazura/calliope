## 3. 'track' と t_end の設計

### 3.1 dt の決め方

Stage 4 までの `reset_dt` は、dt_cfl が dt を下回ったときに dt を下げるだけで、dt_cfl が回復しても dt を上げなかった。
'decrement' で走らせた `turb1_N128_a`（32,427 step）では、dt/dt_cfl の平均は t/τ0 ∈ [0,1), [1,2), [2,3) で 0.670、0.260、0.149 で、後半は dt_cfl の 1/4–1/7 で進んでいた。
'track' は、dt を次の 2 つの場合に track_safety·dt_cfl に置き直す。

- dt_cfl < dt のとき（下げる）。
- `can_increase` が真で、dt < track_raise·dt_cfl かつ dt < increase_dt のとき（上げる）。

どちらでも dt は increase_dt を超えない。dt_cfl が 0 以下か非有限のときは何もしない。
'track' は `reset_dt` の先頭の別の分岐で処理して return するので、'multiply'、'decrement'、'stop' と increase_dt の処理は 1 行も変わらない。
第 3 引数を省いた呼び出し（他の 7 モデル）では `can_increase` は真として扱う。
'track' を選んだときは 0 < track_raise < track_safety ≤ 1 と track_digits ≥ 1 を確かめ、外れていれば値を出して停止する。

上げた直後の dt は track_safety·dt_cfl の切り下げ（3.3 節）で、track_raise·dt_cfl より大きいので、次の step ですぐに「上げる」の条件を満たすことはない。
track_safety と track_raise の差（既定で 0.8 と 0.7）は、dt_cfl の小さな揺れで上げ下げを繰り返さないための幅である。

### 3.2 dt を上げる step の制限

MHD_COMP_ISOTH の dt_visc は ES-SVV の剛性 λ_svv から決まる。
λ_svv はべき乗法で求め、svv_pi_check = 100 step ごとの確認 step でだけ収束まで反復し（許容誤差 1e-3、最大 200 回）、それ以外の step では 1 回だけ反復する。
1 回の反復の λ_svv は収束した値より小さく出ることがあり、`turb1_N128_a` の 326 回の確認 step では、確認 step の λ_svv と直前の step の λ_svv の比は最大 1.193、99 パーセンタイル 1.043、中央値 1.000 だった。
小さく出た λ_svv で dt を上げると、dt が本当の dt_cfl を超えるおそれがある。
そこで ISOTH は `can_increase = (pi_check .and. pi_conv) .or. .not. svv_es` を渡し、dt を上げるのを、べき乗法が収束した確認 step に限る。
下げる判定は毎 step 行う。

上げる step を 100 step ごとに限っても、step 数は 3% 以上は増えない。
`turb1_N128_a` の dt_cfl(t) の上で 'track' を 3τ0 まで模擬すると（track_safety 0.8、切り下げなし）、毎 step 上げてよい場合と 100 step ごとの場合で、step 数は track_raise = 0.5 では 13,418 と 13,388、0.7 では 11,935 と 12,251 だった。
ただし、毎 step 上げる場合は収束していない λ_svv で dt を上げるので、比べるための値でしかない。

確認 step で走りを止める条件 max(dt_prev, dt)·λ_svv ≤ 2.51（RK3 の安定域）は変えていない。
各 step の始めに dt ≤ dt_cfl が成り立つ点は 'decrement' と同じで、この条件の最悪値（2 × 1.193 = 2.39）も変わらない。

### 3.3 dt の切り下げ（track_digits）

'track' は dt を track_safety·dt_cfl から決めるので、dt_cfl の丸め誤差が dt に入る。
dt_cfl は場から決まり、和の順序が MPI の分割で変わるので、分割ごとにわずかに違う。
とくに λ_svv は差分ヤコビアン J v ≈ (G(U + h v) − G(U))/h（h = 1e-7）によるべき乗法で求めるので、場の丸め誤差（1e-15 程度）を 1/h 倍ほどに増幅し、分割ごとに 1e-11–3.5e-10 違う（6.1 節）。
この差が dt に入ると、次の step から場の差が丸め誤差を超えて育つ。
'decrement' と 'multiply' は dt を離散的な値に変えるので、この問題が起きなかった。

'track' は、x = track_safety·dt_cfl を有効数字 track_digits 桁（既定 3）に切り下げた値を dt とする。

```fortran
x  = track_safety*dt_cfl
q  = 10.d0**(floor(log10(x)) - track_digits + 1)
dt = min(aint(x/q)*q, increase_dt)
```

x の相対誤差 δ が切り下げの刻み q/x（1e-3 と 1e-2 の間）の境界をまたがない限り、dt は分割によらずビット単位で一致する。
境界をまたぐ確率は 1 回の dt の変更につき δ/(q/x) ≤ 1e-10/1e-3 = 1e-7 である。
同じく、dt を下げる step（dt_cfl が dt を下回る最初の step）がずれる確率も、dt_cfl の 1 step あたりの変化が相対で 1e-3 程度なら 1e-7 程度である。
切り下げで失う dt は x の 1% 未満である。

### 3.4 終了時刻 t_end

dt が上がると、nstep を固定した実行や連鎖は t_end を越えてしまう。
そこで `time_parameters` に t_end（既定は huge）を足し、`t_end_reached()`（tt ≥ t_end − dt/2）が真になった step の出力の後で主ループを抜ける。
既定値では `t_end_reached()` は偽なので、既存の実行は変わらない。
ISOTH の最終状態の monitor（RHS を評価しない `get_nonlinear_terms` の呼び出し）は、`istep_adv == nstep` に加えて `t_end_reached()` のときも書く。

job script は、ファイル t_end のあるケースを t_end まで連鎖させる。
calliope.in に t_end のないケース（Stage 4 の 'decrement' のケース）は、今までどおり cfl.dat の最後の行の dt から残りの step 数を求める。
calliope.in に t_end のあるケースは Fortran 側が t_end で止まるので、nstep には calliope.in の値（上限）をそのまま使う。
どちらでも、続きの dt は cfl.dat の最後の行から取る。

## 4. 既定値の根拠

| 係数 | 既定値 | 根拠 |
|---|---|---|
| track_safety | 0.8 | 1 回の反復の λ_svv は収束した値の最大 1/1.193 だった（3.2 節）。0.8 × 1.193 = 0.95 ≤ 1 なので、収束していない λ_svv で dt を下げた直後でも、dt は収束した λ_svv による dt_cfl を超えない。0.9 では 1.07 になる |
| track_raise | 0.7 | 下の表。0.8 との差（約 14%）を上げ下げの往復を防ぐ幅として残す |
| track_digits | 3 | 分割による dt_cfl の相対差 1e-10 を dt から除く（3.3 節）。失う dt は 1% 未満 |
| t_end | huge | 既存の実行を変えない |

track_raise は、`turb1_N128_a` の dt_cfl(t)（cfl.dat の dt_adv と dt_visc の小さいほう）の上で 'track' を 3τ0 まで模擬して選んだ（上げるのは 100 step ごと）。
選んだ時点では切り下げ（3.3 節）を入れておらず、その列を左に置く。右の列は切り下げを 3 桁で入れて同じ模擬をした値である。

| track_safety | track_raise | step 数（切り下げなし） | `turb1_N128_a` の 32,427 step との比 | dt の変更 | step 数（3 桁の切り下げ） | dt の変更 |
|---|---|---|---|---|---|---|
| 0.8 | 0.5 | 13,388 | 0.413 | 11 | 13,537 | 11 |
| 0.8 | 0.7 | 12,251 | 0.378 | 17 | 12,194 | 18 |
| 0.9 | 0.8 | 11,173 | 0.345 | 29 | 11,168 | 30 |

dt の変更は、ジョブの区切りを生まない（3.4 節）ので、変更の回数は損失にならない。
0.9 と 0.8 の組は step 数をさらに 9% 減らすが、track_safety = 0.9 は上の表の条件を満たさない。

## 6. MPI の分割によらない dt

### 6.1 切り下げを入れる前の失敗

'track' の最初の実装は dt = track_safety·dt_cfl と置き、切り下げをしなかった。
この実行ファイルで、turb1 の 64³ を dt0 = 0.3 dt_cfl(0) から 400 step、P = 1, 8, 64 で走らせた（`runs/stage6/track/dec_N64_np*`、job 483322）。
dt0 を小さく取ったのは、100 step 目の確認 step で必ず dt を上げさせるためである。
判定の基準は、計画の時点で「cfl.dat の dt の列が P によらずビット単位で一致」と「E_K、E_M、ρ_min の P = 64 との差が列の最大値の 1e-10 以下」と決めた。

dt を変えた行（100 と約 300）は P によらず一致したが、dt の列の差は P = 1 で 3.1e-9、P = 8 で 4.0e-9 あり、E_K、E_M、ρ_min の差も 1.2e-10–8.2e-10 あった。
原因は、次のように切り分けた。

1. dt を固定した 100 行目までは、E_K の差は 4.7e-15 以下、ρ_min の差は 2.6e-16 以下で、場は丸め誤差の範囲で一致していた。
2. この間に λ_svv は分割ごとに 1e-11–3.5e-10 違っていた。べき乗法の反復回数は P によらず同じだった。3.3 節のとおり、差分ヤコビアンが場の丸め誤差を 1/h 倍に増幅するためである。
3. 100 行目で dt を上げたとき、dt は 0.8 dt_visc（dt_visc = 2.96e-3 < dt_adv = 3.98e-3）となり、P = 1 で 7.6e-12、P = 8 で 1.2e-11 だけ P = 64 と違った。
4. 以後、場の差は 200 行目で 1e-12、399 行目で 1.4e-10 に育ち、約 300 行目の 2 回目の変更で dt の差は 3.8e-9 になった。

### 6.2 切り下げを入れた後

3.3 節の切り下げ（track_digits = 3）を入れ、同じ 3 ケースを `runs/stage6q/track` で走らせ直した（job 483581）。
判定の基準は 6.1 節と同じである。

| P | dt を変えた行 | dt の列の差 | E_K の差 | E_M の差 | ρ_min の差 |
|---|---|---|---|---|---|
| 1 | 2 回（上げたのは 100 行目） | 0 | 4.6e-15 | 5.4e-15 | 4.4e-16 |
| 8 | 2 回（上げたのは 100 行目） | 0 | 6.9e-16 | 9.1e-16 | 3.9e-16 |

差は P = 64 との差を列の最大値で割った値である。
dt の列はビット単位で一致し、場の差は 400 step を通して丸め誤差の範囲にとどまった。
dt を上げた行は確認 step（100 の倍数）だけだった。

## 7. 'track' で走らせた乱流と Stage 4 の実行の比較

'track' が結果を変えないことを、turb1（M_s = 1）の 64³ と 128³ を 3τ0 まで走らせて確かめた（`runs/stage6q/track/turb1_N64_t`、`turb1_N128_t`）。

判定の基準は、結果を見る前に次の 3 つと決めた。

- ε のピーク値とその時刻、t/τ0 = 1, 2, 3 での E_K、E_M、ρ_min、ρ_max の Stage 4 との相対差 d_track が、max(0.1 d_res, 1e-3) 以下である。d_res は同じ量の Stage 4 の 64³ と 128³ の相対差で、解像度による差を表す。
- 全 step で dt ≤ dt_cfl である。
- 確認 step の max(dt_prev, dt)·λ_svv が 2.51 以下である。

| ε のピーク時刻 | 2.86e-1 | 2.86e-2 | 4.29e-5 | 1.06e-4 |

| ケース | step 数 | Stage 4 との比 | 模擬の予測 | dt の変更（上げた回数） | max dt/dt_cfl | 確認 step の max dt·λ_svv |
|---|---|---|---|---|---|---|
| turb1_N64_t | 5,017 | 0.703 | 5,019 | 12（8） | 1.0000 | 1.521 |
| turb1_N128_t | 12,052 | 0.372 | 12,194 | 21（12） | 1.0000 | 1.639 |

max dt/dt_cfl が 1.0000 なのは、dt_cfl が上から dt に近づいた step で比が 1 に近づいたためで、1 を超えた step はなかった。
dt/dt_cfl の平均は、t/τ0 ∈ [0,1), [1,2), [2,3) で 128³ が 0.854、0.782、0.801 だった（Stage 4 の 'decrement' では 0.670、0.260、0.149）。
step 数は、3 桁の切り下げを入れた模擬の予測と 64³ で 0.04%、128³ で 1.2% 違った。

エネルギー収支の時間離散化の残差（各 step の実際の E の変化と RK の段の率の和との差を 3τ0 にわたって足した値）は、dt が大きくなった分だけ増えた。

3τ0 の間に変化する E（−192 と −190）に対する比は、'track' の実行でも 2.1e-6 と 1.3e-6 にとどまる。

## 8. turb1 の 256³ と 64³、128³ との収束

### 8.1 実行と比べる相手

`runs/stage6q/turb/turb1_N256` は、turb1（M_s = 1）の 256³ を 256 rank、'track'、t_end = 3τ0 で走らせたケースである。
初期場、係数、出力の設定は Stage 4 の `turb1_N64` と `turb1_N128_a` と同じで、収支の診断（`budget`）は毎 step 書いた。
A_dev の 30 分のジョブを 16 本連鎖させ、40,064 step で t = 3τ0 に達した。
連鎖のつなぎ目は `check_seams.py` で確かめ、15 か所のすべてで時刻の隙間は 0、E の飛びは 8.5e-14 以下だった。

比べる相手は Stage 4 の `turb1_N64`（固定 dt）と `turb1_N128_a`（'decrement'）である。
7 章で、'track' による結果の違いが解像度による違いの 1/100 未満であることを確かめたので、dt の決め方の違う実行どうしを比べてよい。
収束の判定には Stage 4 の S4.3 の条件をそのまま使い（`analyze_stage4.turb_convergence`）、差は |a − b|/b（b は細かいほうの格子の値）とした。
以下、時刻は τ0 を単位とする（コードの時間で τ0 = π）。

### 8.3 散逸率

散逸率 ε(t) と ε_shock（破線）を図 `fig/stage6_turb_eps.png` に示す。
ε の最大値は 64³ で 35.3（t = 0.755τ0）、128³ で 36.5（1.058τ0）、256³ で 38.5（1.121τ0）である。
128³ と 256³ の差は値で 5.2%、時刻で 5.6% で、64³ と 128³ の差（3.1% と 29%）と比べると、時刻の差は縮み、値の差は広がった。
ε が最大値の 95% 以上にある時間は、64³ で 0.57–1.02τ0、128³ で 0.92–1.15τ0、256³ で 0.99–1.26τ0 である。
256³ の ε は 0.87–0.93τ0 に細かく揺れる（この節の最後の段落）ので、幅 0.02τ0 と 0.05τ0 の移動平均でも最大値を求めた。
128³ と 256³ の差は、幅 0.02τ0 で値 5.4%、時刻 5.8%、幅 0.05τ0 で値 4.9% だった。
幅 0.05τ0 では値の差が S4.3 の 5% を下回るが、時刻の差と他の項目（8.5 節）が不合格なので、判定は変わらない。
[0, 3τ0] の散逸の総量は 192.0、189.6、188.5 で、N を倍にするごとに 1.3%、0.6% 違う。

ε_shock の割合は N を倍にするごとに 0.87 倍、0.88 倍になり、減った分を SVV（u）が担う。
SVV（B）の割合は 0.30–0.31 でほとんど変わらない。

t = 0.5τ0 の ε は N とともに 32.9、22.7、16.8 と下がる。
128³ と 256³ の差 5.9 のうち ε_shock の差は 1.0 で、残りは SVV の差である。
Stage 4 が 64³ について推定したのと同じく、粗い格子の SVV が、乱流が広がる早い時刻にエネルギーの多い波数を直接散逸させていると考えている。
t = 2τ0 の ε は 14.7、16.7、19.4 と N を倍にするごとに 14%、16% 増え、収束していない。

Stage 4 の 8.4 節は、64³ と 128³ の ε_shock が t ≥ τ0 でほぼ重なることと a90 の比（8.6 節）から、「M_s = 1 の ζ の散逸は格子幅の衝撃波ではなく、広い領域の滑らかな圧縮が担っている」と読んだ。
256³ を加えた ε_shock の N 依存は、この読みと合わない。
ε_shock は ρ ζ D² の体積積分である（D は速度の発散）。
圧縮が格子で解像されていれば D は Δ によらず、ζ ∝ Δ² なので ε_shock ∝ Δ² となる。
格子幅の衝撃波では D ∝ 1/Δ、ζ ∝ Δ で、衝撃波の占める体積が Δ に比例するので、ε_shock は Δ によらない。
ε_shock ∝ Δ^p と置くと、256³ と 128³ の比（t/τ0 = 0.5, 1, 2, 3 で 0.91、0.91、0.84、0.77）から p は 0.13、0.13、0.25、0.38 で、滑らかな圧縮の 2 より衝撃波の 0 に近い。
ε_shock を Δ によらない成分と Δ² に比例する成分の和と仮定すると、128³ の ε_shock のうち Δ² の成分は t/τ0 = 1, 2, 3 で 12%、21%、31% にとどまる。
この N 依存は、ε_shock の大部分を格子幅まで急峻になった圧縮が担うとすれば説明できる。
ただし、a90 の比はこの説明とも合わない（8.6 節）。

256³ の ε は、ρ の穴が深い 0.866–0.933τ0（8.7 節）に細かく揺れる（図の t ≈ 0.9τ0）。
この期間の ε の標準偏差 1.6 に対し、SVV の分の標準偏差は 1.6、ε_shock の分は 0.14 で、揺れは SVV から来ている。
step ごとの ε の変化の絶対値は中央値 0.011、最大 0.100 で、その前の 0.764–0.828τ0 の 0.005、0.027 の 2–4 倍だった。
揺れが穴の点の SVV から来ているかどうかは調べていない。

### 8.4 スペクトルと解像できる波数帯域

全エネルギーのスペクトル E_tot(k) を図 `fig/stage6_turb_spec.png` に示す（左が t = τ0、右が 3τ0、縦の点線は各 N の k_c）。

t ≤ 1.5τ0 の k_eff は N に比例して広がり、128³–256³ の 30–32 は 128³ の m_N = 21.3 と k_c = 42.7 の間にある。

t ≥ 2τ0 の k_eff は 19、18、15 に下がる。
これは切断の近くで合わなくなるためではなく、粗い格子のスペクトルが k_c より下の帯域で細かい格子より高くなるためである。

SVV のかかり始めの手前にエネルギーが溜まっている（bottleneck）可能性があるが、確かめていない。
t = 3τ0 では、どちらの組の k_eff もこの超過で決まり、粗い格子の m_N より下にある。
超過が 25% を超える最初の k は、64³–128³ で 7（64³ の m_N の 0.66 倍）、128³–256³ で 16（128³ の m_N の 0.75 倍）である。
この位置の違いのために、k_eff の比は 2 でなく 2.5 になり、条件 [1.7, 2.3] を外れた。

解像される衝撃波の本数が N とともに増えれば、面積は Δ ほどには減らないが、本数は数えていない。

0.893τ0 の穴は、x と y の隣の ρ が 0.08–0.24 で、1–2 格子点の幅である。
0.578τ0 では移流が穴を埋め、SVV が掘る（Stage 5 の `turb4b` と同じ向き）。
0.893τ0 では移流が穴を掘り、SVV が埋め戻す（`turb4` と同じ向き）。
どちらの時刻でも正味の dρ/dt は正だが、ρ_min はその後 0.902τ0 に 0.0090 まで下がった。
最小の点が移ったのか、同じ点で収支の符号が変わったのかは調べていない。
穴の深さを決める機構は、この 2 時刻の内訳だけでは決められない。

確認 step 389 回のうち 81 回で、べき乗法は 200 回の反復で許容誤差 1e-3 に収束しなかった。
収束しなかった step は t = 0.80–1.02τ0、1.07–1.24τ0、1.77τ0 にあり、ρ_min の低い時期に重なる。
これらの step の λ_svv は、同じ step の 1 回の反復の λ_svv の 0.996–1.006 倍、次の step の λ_svv の 0.993–1.005 倍で、値は 0.7% 以内に定まっている。
収束しなかった step では dt を上げない（3.2 節）ので、これらの step の dt λ_svv の最大は 1.954 で、2.51 の内側にとどまった。

## 9. 計算の速さ

### 9.1 dt の決め方と step 数

| ケース | dt の決め方 | step 数 | dt の変更（上げた回数） | max dt/dt_cfl | 確認 step の max dt·λ_svv | dt/dt_cfl の平均（t/τ0 ∈ [0,1), [1,2), [2,3)） |
|---|---|---|---|---|---|---|
| `turb1_N64` | 固定 | 7,134 | 0 | 0.976 | 1.513 | 0.757、0.599、0.340 |
| `turb1_N128_a` | 'decrement' | 32,427 | 3（0） | 0.9999 | 1.727 | 0.670、0.260、0.149 |
| `turb1_N256` | 'track' | 40,064 | 82（38） | 1.0000 | 1.954 | 0.807、0.803、0.825 |

256³ の dt は 1.39e-5 と 7.27e-4 の間で 82 回変わり、dt/dt_cfl の平均は 3τ0 を通して 0.80–0.83 にとどまった。
計画では、256³ の step 数を 128³ の 'track' の 2.58 倍の 3.2e4（2.5e4–3.7e4）と見積もった。
実際の 40,064 step は 128³ の 'track'（12,052 step）の 3.32 倍で、見積もりの上限を超えた。
超えた分は、8.7 節の穴の期間から来ている。
5–9 本目（0.818–1.020τ0）の 0.20τ0 に、全体の 28.7% にあたる 11,497 step を使った。
残りの 11 本は 2.80τ0 を 28,567 step で進み、1τ0 あたり 1.02e4 step で、128³ の 'track' の 3τ0 の平均（1τ0 あたり 4.0e3 step）の 2.54 倍だった。
128³ でも 0.9τ0 の近くで dt が縮むので、この比は目安である。

### 9.3 全体の計算時間

256³ の 16 本の wall 時間の合計は 24,771 s（6.88 h）で、1 ノード（256 コア）で約 1,761 core-h を使った。
1–15 本目はそれぞれ 1,576–1,593 s 走り、16 本目は t_end に達して 1,060 s で終わった。
平均の 1 step は wall で 0.618 s、solve で 0.592 s である。
計画の見積もり（3.2e4 step × 0.58 s ≈ 5.1 h、4.0–5.9 h、10–15 本）と比べると、1 step の時間は 2% の違いに収まり、超えたのは step 数（9.1 節）のためである。

3 つの N の 1 step の時間は次のとおりである。

| N | rank 数 | solve（s/step） | wall（s/step） | 1 rank の受け持つ格子点 1 つあたりの solve（s） |
|---|---|---|---|---|
| 64³ | 64 | 0.0335 | 0.0365 | 8.2e-6 |
| 128³ | 128 | 0.0984 | 0.1015 | 6.0e-6 |
| 256³ | 256 | 0.592 | 0.618 | 9.0e-6 |

3 つの実行は 1 ノードあたりの rank 数も診断の出力間隔も違うので、この表は並列性能の試験ではない。
並列性能は Stage 4 の S4.5 で調べた。

## 10. 実装した範囲と未実装の範囲

### 10.1 実装し、実行したもの

- 共通の `src/time.F90` に、既定ではオフの `reset_method = 'track'` と、その 3 つの係数、終了時刻 t_end を入れた（3 章）。
  'track' は dt を dt_cfl に追従させて上げ下げする。係数の既定値の根拠は 4 章に記した。
- ISOTH では、べき乗法が収束した確認 step に限って dt を上げるようにした（3.2 節）。
- 既定の設定で、ISOTH の 7 組と MHD_INCOMP の 1 組の出力が変更前と一致することを確かめた。他の 5 モデルはビルドが通ることを確かめた（5 章）。
- 'track' の dt が P = 1, 8, 64 でビット単位で一致することを確かめた（6 章）。
  最初の実装はこの基準を満たさなかったので、原因を調べて dt の切り下げ（track_digits）を加えた。
- turb1 の 64³ と 128³ を 'track' で 3τ0 まで走らせ、Stage 4 の実行との差が解像度による差の 1/10 を大きく下回ることを確かめた（7 章）。
- turb1 の 256³ を、floor も粘性も足さずに 'track' で 3τ0 まで走らせた（16 本の連鎖、40,064 step）。
  つなぎ目は `check_seams.py` で確かめ、非有限値は出なかった（8.1、8.2 節）。
- 64³、128³、256³ の収束を、Stage 4 の S4.3 の条件のまま評価した（8.3–8.6 節）。128³ と 256³ の組は不合格だった。
- 256³ で ρ の穴が深まった期間の dt、F_svv、穴の点の dρ/dt の内訳を調べた（8.7 節）。
- `analyze_stage6.py turb` が、連鎖のジョブごとの step 数、1 step の時間、タイマーの割合、べき乗法の反復回数を出すようにした（9.2 節）。

### 10.2 実装しなかったもの、走らせなかったもの

- ISOTH 以外のモデルで 'track' を使う試験。
  他のモデルは `reset_dt` を 2 引数で呼ぶので、'track' を選ぶと dt_cfl を求めるたびに dt を上げうる。この使い方は試していない。
- 512³ の実行。取り決めにより、3D は 256³ までとした。
- M_s > 1 の乱流を 'track' で走らせること。Stage 5b の後、対象を M_s ≤ 1 に絞った。
- 256³ の ρ の穴の深さを決める機構の特定。穴の点の dρ/dt の内訳は 2 つの時刻でしか求めていない（8.7 節）。
- 穴の期間の ε の細かい揺れ（8.3 節）と、粗い格子のスペクトルが m_N の前後で高くなる仕組み（8.4 節）の原因の調査。
- べき乗法が 200 回の反復で収束しない step への対処（8.7 節）と、収支の診断の時間（solve の 18%、9.2 節）を減らすこと。

## 11. 未解決の問題

- 'track' の dt が MPI の分割によらず一致するのは、track_safety·dt_cfl の分割による違い（相対 1e-10 程度）が 3 桁目の切り下げの境を越えない場合に限る。
  越える確率は dt の変更 1 回につき 1e-7 程度と見積もった（3.3 節）。越えた場合も dt の違いは切り下げの刻み 1 つ分（相対 1% 以下）で、dt ≤ dt_cfl は保たれる。
- EMHD と MHD_COMP_ADIAB は分岐前からビルドが通らない（5 章）。今回は直していない。
- `runs/stage6/turb/turb1_N256` は、切り下げを入れる前の実行ファイルに合わせて作ったケースで、走らせていない。256³ の結果はすべて `runs/stage6q/turb/turb1_N256` から得た。
- ρ_min は N とともに下がり、128³ と 256³ の間でも収束しない（ρ の範囲の下限は 0.057 と 0.0090、8.2、8.5 節）。
  穴が深い期間には dt が 1/10 に縮み、3τ0 の step の 29% をその 0.20τ0 に使った（9.1 節）。
  512³ では穴がさらに深まり、dt がさらに縮むおそれがある。走らせる前に、穴の機構（8.7 節）を調べる必要がある。
- べき乗法は、ρ_min の低い時期の確認 step 389 回のうち 81 回で、200 回の反復で収束しなかった。
  λ_svv の値は 0.7% 以内に定まっていて、その step では dt を上げないので、安定は保たれた。
  ただし、その間は 1 step の時間が 1.2 倍に延びた（9.2 節）。
- S4.3 の a90 の条件は t = 0 を含む全時刻に当てるので、滑らかな初期場では t = 0 で必ず外れる（8.6 節）。
  t = 0 を除いても今回の判定は変わらないが、条件の決め方を見直す必要がある。
- ε_shock の N 依存（256³/128³ の比 0.77–0.91）と a90 の比（t ≥ τ0 で 0.67–0.94）は、同じ 1 つの描像で説明できていない（8.3、8.6 節）。
  Stage 4 の「M_s = 1 の ζ の散逸は広い領域の滑らかな圧縮が担う」という読みは、256³ を加えると支持されない。
- t ≥ 2τ0 の k_eff は粗い格子の m_N より下にあり、粗い格子のスペクトルが細かい格子より高くなる帯域で決まる（8.4 節）。
  t = 3τ0 では k_eff の比が 2.5 になり、条件を外れた。
